## 先测B图

上传 `B-one-visible-label-two.png` 到“封箱前货物照片”列，用下文指令运行“实物数量AI核对”。输出1件并指出与标签2不符，才通过此样本。若输出2件或将标签QTY当成实物总量，记为失败。再测A和C；有限合成样本不能推出真实业务准确率。

可以在同一条模拟记录上依次替换这三张图，每次仅生成该记录结果并记录输出。不要将三张图同时放进一个附件单元格，否则任务变成多图汇总。保留现有“照片”标签图与原始识别结果，不覆盖它们。

## 脚本建列与AI配置的区别

`create_feishu_columns.py` 使用Python标准库，无需额外安装库。它只在“发货核对”表新增缺少的12列，不修改原有列或记录，不上传图片，不调用AI。同名列类型或单选选项冲突会停止；重跑跳过已存在列。

| 字段 | 类型 |
|---|---|
| 封箱前货物照片 | 附件 |
| 实物数量AI核对 | 文本；建好后在飞书设置豆包图片理解 |
| 可见对象及位置 | 文本 |
| 可见完整商品数量 | 数字 |
| 可见包装数量 | 数字 |
| 实物总数量是否能确定 | 单选：可确定/无法确定/待核对 |
| 图片中的SKU | 文本 |
| 实物与标签是否一致 | 单选：一致/不一致/无法判断/待核对 |
| 人工确认实物数量 | 数字 |
| 实物核对状态 | 单选：待核对/已确认/异常待处理 |
| 实物核对人 | 文本 |
| 实物核对备注 | 文本 |

“实物数量AI核对”保存完整AI输出。其他结果列暂时用于人工记录或后续自动解析；本脚本不会把AI输出自动拆分填入它们。“实物核对人”为文本姓名，不能代替系统身份审计。

## 如希望助手直接建列

当前尚无飞书连接、凭据或目标链接，实际创建未执行。请提供多维表格链接，确认目标是“发货核对”；链接本身不会授予写入权限。

飞书企业管理员可按下面顺序准备授权：

1. 在飞书开放平台创建或选择企业自建应用。
2. 为应用配置多维表格读写权限、适当的数据访问范围；具体权限名称与审批要求按当前控制台及官方文档确认。
3. 按企业要求发布/安装应用，并给该应用访问目标多维表格、编辑目标表的权限。仅有应用密钥不等于表格访问权。
4. 在Codex云环境的安全设置中填写应用标识 `FEISHU_APP_ID`，并通过秘密凭据配置填写 `FEISHU_APP_SECRET`，允许的目标域名为 `open.feishu.cn`。不要将Secret或访问令牌发到聊天、写入代码或提交GitHub。
5. 保存配置后，助手重新检查网络、认证、目标表及字段；先显示只读检查结果，再执行已获授权的新增缺少列操作。

官方参考：
- https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-field/create
- https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal

本环境访问官方文档曾返回代理403，脚本接口形状基于已知开放API，尚未与真实飞书联调。管理员应按当前文档核实应用权限、附件字段、字段创建和单选配置行为。不要把本地模拟接口测试报告成真实建列成功。

## 技术人员执行方式

离线查看字段清单，不需要凭据：

```bash
python create_feishu_columns.py --show-schema
```

凭据通过安全环境配置注入后，先只读检查（下例链接为占位符）：

```bash
python create_feishu_columns.py --url 'https://YOUR-TENANT.feishu.cn/base/APP_TOKEN?table=TABLE_ID'
```

确认目标正确后执行新增（用户已经请求建列，助手无需重复索要同一操作的许可）：

```bash
python create_feishu_columns.py --url 'https://YOUR-TENANT.feishu.cn/base/APP_TOKEN?table=TABLE_ID' --apply
```

如果提供的是知识库`/wiki/`链接，需先获得真实多维表格标识；当前脚本不自动解析知识库链接。网络超时后先查询现有字段，不盲目重复创建。
